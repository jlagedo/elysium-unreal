# Brief L2.rpg.rpg-strings-1 — RPG string table

Layer L2 · story `L2.rpg.rpg-strings` · slice 1 of 1 · **ready**

## Goal

Implement the string table’s identity and lookup contract before its catalogue callers.. The story: Reproduce append, duplicate reuse, ID assignment and lookup for the RPG string table at 0x10202d10, 0x10202e50, 0x102037f0, 0x10202b10, 0x10203bb0 and 0x10203c00. Preserve retail IDs and lookup results.

## The retail functions (read each body before writing: `vtmb_code <address>`)

- `0x10202d10` Global::FUN_10202d10 (246 B, 108 maps, partial) — Append or reuse a string-table object, growing capacity by four and assigning a monotonically increasing table ID. Port lacks: FindOrAdd creates string groups using Unreal containers, but no equivalent sequential numeric table-ID registry or append/reuse semantics was found.
- `0x10202e50` Global::FUN_10202e50 (72 B, 108 maps, partial) — Allocate a named string table, load its formatted entries, store its flag, and return its ID or -1. Port lacks: Named Name<N> lists are loaded, but the numeric ID return, per-table flag, and caller-selected entry format are absent; repeated groups are merged.
- `0x102037f0` Global::FUN_102037f0 (184 B, 108 maps, partial) — Read string-table data through a parser, store its header/default and entries, intern strings, and release parser storage. Port lacks: Indexed string entries are loaded into FString arrays, but the extra header/default output is not retained; bare Name fields are explicitly skipped. Exact parser-output equivalence remains uncertain.
- `0x10202b10` Global::FUN_10202b10 (102 B, 108 maps, partial) — Load a named VStringTable through the string-array reader and return success or failure. Port lacks: The port loads named groups from string files, but exposes file-level success rather than this per-table result and omits the reader's header/default state.
- `0x10203bb0` Global::FUN_10203bb0 (49 B, 108 maps, partial) — Load common Strings and Tables support blocks from strings, strings_internal, and rules_tables under their respective roots. Port lacks: Both string files and rules_tables are loaded by separate loaders. The generic Strings-and-Tables handling for every file and fatal load-failure behavior are not reproduced.
- `0x10203c00` Global::FUN_10203c00 (177 B, 108 maps, partial) — Loads a system data file and merges its Strings and Tables blocks into global catalogues. Port lacks: String merging and rules_tables loading are folded into separate loaders. Retail's generic Strings/Tables handling and fatal load-failure behavior are not fully preserved.
