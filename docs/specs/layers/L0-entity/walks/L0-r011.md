The emitted text form is `tag=<tag> fn=<retail symbol> va=0x<VA> phase=<phase> <payload>`, emitted at the port line that carries the address. The tags below are proposals; none exists yet.

### l0_particle_spawn

- Probes: `particle_spawn` (`fn=CEnvParticle::Spawn va=0x100fb3d0`), phases `entry`, `attach`, `bounds`, `parent`, `active`, `remove`. Payload `attach_type=<in> -> <out>`, `bounds=<in> -> <out>`, `def=<+0x454>`, `parent=<resolved|none>`, `active_stamp=<curtime>`.
- Expect (retail):
  - Attach type 19 (or any negative) gives `attach_type 19 -> 0` and a Warning (`entity %s has invalid attach type!`). It fires before the definition test, so it also fires on an entity that is then removed.
  - Bounds 5000 gives 4096; -3 gives 0; a value inside the range is unchanged. Bounds are only touched when the definition resolved.
  - A valid emitter has `m_bActive == 1` and `+0x488 == curtime at spawn` (the constructor already wrote the creation time; Spawn restamps it). Probe `+0x488` (SendTable name `m_flActivationTime`) via the retail_site payload.
  - The definition with `+0x454 == -1` is removed. In retail that value arises only from a NULL `m_sParticleDefinition` (the engine precache never returns a negative), so the arena fixture for the unresolved entity must be an emitter with **no** `particle_definition` key, not one naming a missing file. Removal runs UpdateOnRemove and `SetName(NULL)`, queues the node for deferred deletion, and emits no SUB_Remove warning.
  - A definition path is reduced to its base name before the precache (`dir/foo.ext` gives `foo`); the retail string is not lowercased.
- Parent: the valid emitter with an existing parent should show `m_nAttachPoint` (`+0x460`, named), SetMoveType 11 through its movetype, the aim entity set, and a zeroed local origin. The port defers this to TurnOn, so the record will fail on the parent expectation unless the attachment story is closed first.

### l0_particle_ramp_time

- Probes: `particle_ramp` (`fn=CEnvParticle::InputSetRampTime va=0x100fb8a0` or `FUN_100fba40 va=0x100fba40`, `phase=write`), and `fn=FUN_100fb980 va=0x100fb980` for SetRateScale.
- Expect (retail):
  - SetRampTime(1.0) at frame F0 gives `m_fRampTime == 1.0` and `+0x494 == F0`, where F0 is the **host frame counter** (an integer that increases by one per engine frame), not a time. The arena witness has to expose the frame counter (or the port frame index) beside the time.
  - SetRateScale(0) at a later frame F1 gives `m_fRateScaleTarget == 0` and `+0x494 == F1`. So any later read of `+0x494` returns F1, not the SetRampTime frame. The story wording "distinguish the stored SetRampTime clock from starting the ramp on SetRateScale" cannot be tested this way, because SetRateScale overwrites the stamp.
  - The discriminating probe is a SetRampTime at a still later frame F2 after the SetRateScale at F1. Retail sets `+0x494 = F2` while `+0x48c` stays 0. The port has no stamp, so it diverges here.
  - Negative ramp time gives a Warning and `m_fRampTime == 0`. A non-float input variant gives `0.0` and no Warning.
- The reader of `+0x494` is not on the server: the walk found no vampire.dll function in the CEnvParticle range that reads it, and `DT_EnvParticle` sends it as `m_nRampFrame` (the client table `FUN_100ae6d0` receives it). UNRECOVERED: the client ramp that consumes it; the datamap also lists a think `CEnvParticleRampDown_Think` whose body is unrecovered.

### l0_world_sweep_query

- Probes: `world_clear` (`fn=FUN_1023f3d0 va=0x1023f3d0`) with payload `start=... end=... fraction=1 contents=0 allsolid=0 startsolid=0`. Expect `end == start + delta`.
- `segment_sphere` (`fn=FUN_1023ffa0 va=0x1023ffa0`) with payload `p=... t=... dist2=... rs2=... result=0|1`.
  - Exact touch (`dist == r1 + r2`) gives 1.
  - Just outside gives 0.
  - Negative radii sum: `r1 = -3, r2 = 1` gives `rs2 = 4`, so the test is against two units.
  - `p <= 0` gives `t = 0` (closest is A), including `D = 0`.
  - `p > |D|^2` gives `t = 1`.
  - Realistic radii: the only caller passes `r1 = |ray extents| + |box half size|` and `r2 = tolerance`.

### l0_runtime_decal

- Unnamed `infodecal`: `decal_spawn` (`fn=CDecal::Spawn va=0x1023a750`), payload `texture=<+0x450> spawnflags=<+0x204> mp_byte=<gpGlobals+0x30> path=unnamed`. Then `decal_project` (`fn=FUN_1023aa30 va=0x1023aa30`) with payload `min= max= mask=0x200400b hit=<none|idx> model=<n> local=<x y z> submit=(origin, texture, eidx, model)`.
  - Expect: when the trace misses **or hits the world** (edict index 0), the submit is `(world origin, texture, 0, 0)`. A hit on a brush or other entity with a non-zero edict index submits `(local point, texture, eidx, model)`. Then `removed`.
  - The `texture` payload is the index from the `texture` key (`PrecacheDecal`), so the fixture needs the key; a decal with no key submits index 0.
- Named counterpart: `decal_spawn path=named`. Expect `+0x1f0 == 0x1000c888` and the think no-op. Not removed on spawn.
  - On `decal_use` (`fn=CDecal::Use va=0x1023a7d0`): origin is the local GetOrigin, mask `0x400b`, a `CTEBSPDecal` broadcast to all players `(0.0, local origin, eidx, texture)` and **no StaticDecal, no model, no local transform**. Removed at use + 0.1 s. A trace that hits nothing faults in retail, so the fixture must put a solid under the decal.
  - The story record text ("traces the hit model and local point, submits the decal") for the named path must be restated as "broadcasts a BSPDecal temp entity with the hit edict index".
- Witness note: the two witness maps hold only unnamed infodecals (219 and 123, no `targetname`, no `spawnflags`), so the named path has no witness there.
