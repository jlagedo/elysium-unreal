# Walk L0-r012

Scope: the six CLight functions of brief `L0.effects_world.switchable-light` (slices 1-2), plus the helpers they reach and the datamap rows that route inputs to them. Read-only. All bodies are `vampire.dll`. Bare `0x10130800` and `0x101308d0` also name unrelated `client.dll` functions (`FUN_10130800`, a Plat_Free routine; `FUN_101308d0`, a sound-params initialiser); every address here is the vampire.dll body. Confirmed against the corpus by a second reader (see `## Confirmation`).

## Shared facts

**Constants** (`pe.py const`, `vtmb_asm`):
- `0x10453b74` float `0x3D4CCCCD` = **0.05** (0.0500000007450581). Spawn's fade_time floor (asm `0x1013047e`). The floor is `max(fade_time, 0.05)`: `FCOMP` then `AND 0x4100` / `JNZ` takes the constant when fade_time <= 0.05 or is NaN. It is a literal, not a cvar.
- `0x104454c4` float `0.0` (bytes `00 00 00 00`). A shared zero: ThinkSet's default-time test, the think dispatcher's `thinkTime > 0` test (`0x10033e59`), variant Convert. Not specific to CLight.
- `0x1053f564` `"pitch"` (strcmpi key).
- `0x10540a3c` `"a"` (`0x61`), dark. The next string at `0x10540a40` is `"b"`.
- `0x105758c4` `"m"` (`0x6d`), full/normal brightness.
- `0x106b8540` `""`, the empty fallback.
- `0x1057581c` `"CLightFadeThink"`: the **FUNCTIONTABLE row name** for FadeThink in the CLight datamap (row 5, flags `0x20`, function `0x10012215`), so a saved `m_pfnThink` can be stored by name. It is not a think-context name (ThinkSet is called with a NULL context).

**AcceptInput routing** (`CBaseEntity::AcceptInput` `0x100abc90`, which the datamap rows above feed). It walks the datamap chain (slot 82, then `baseMap`), matches rows with flag `0x8` by `strcmpi` on the external name, records `m_hLastInputActivator` / `m_hLastInputCaller`, and calls the row's function only when `variant.type == row.type` or `variant_t::Convert(row.type)` (`0x100d05d0`) succeeds. Otherwise `DevWarning("!!! ERROR: bad input/output link ...")` and it returns 0 without calling. The function receives an inputdata: `+0` activator, `+4` caller, `+8` the 20-byte variant (value at `+8`, type at `+0x18`), `+0x1C` output id. Convert, as it matters here:
- target VOID (0): always succeeds (calls `0x1000b320`). So `Toggle`/`TurnOn`/`TurnOff` take any parameter.
- target STRING (2): source VOID -> value NULL, type 2 (success); source EHANDLE (12) -> **returns success without changing the variant (type stays 12)**; source FLOAT / INTEGER / BOOLEAN / VECTOR / COLOR32 -> failure, the input is refused.
Hammer-authored output parameters are strings (`docs/vtmb/entity_io.md` "NPC TeleportToEntity"), so `SetPattern` and `FadeToPattern` normally see type 2.

**Think dispatch** (`PhysicsRunSpecificThink` `0x10033de0`, `PhysicsDispatchThink` `0x10033b80`, generic think thunk `0x1000f588` -> `0x1003c450` = `jmp [vtbl+0x218]`, i.e. slot 134 `CBaseEntity::Think`): a think runs only if `m_flNextThink > 0.0` **and** `m_flNextThink <= curtime + frametime`. The dispatcher clamps the think time up to curtime, **clears `m_flNextThink = 0.0` before the call**, rebinds `gpGlobals->curtime` to the think time for the duration of the call, stores `m_flLastThink`, restores curtime, and returns `!(m_iEFlags & 1)`. So `m_flNextThink <= 0.0` is "no think" and `FadeThink`'s explicit `= 0.0` is redundant with the dispatcher's own clear; `CBaseEntity::ScriptHide` (`0x100a8710`) parks a think with `0x7f7fffff` (FLT_MAX) instead.
