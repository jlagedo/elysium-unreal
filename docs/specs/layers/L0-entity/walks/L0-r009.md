     - The retire happens before the channel allocation. The retired record keeps its channel, so the allocator excludes it. When the old track was non-empty, retire clears the whole record, so the new track starts with `+0x44 = 0`; when it was empty, `+0x44` was already 0.
  3. `else` (`volume < 0` or NaN): no writes.
- **Notes:** on every path that reaches here, `duration >= 0.5` after the clamp in `0x1022b590` (the FadeOut path through `0x1022b520` does not call this function), so the division is safe except for NaN. `+0x48` is the authored volume (the ceiling) and `+0x40` the target; the record's `+0x44` current level is **not** written here, so the new track ramps from 0 toward `volume` at `volume / duration` per second (it reaches the target after `duration` seconds) through `FUN_10229090`, which also emits the sound. A same-name retarget keeps the current `+0x44` and ramps from there at the new rate. The music-state gate (`FUN_10228e80`) then rewrites the target of the Music, Combat and Alert slots on the next frame, so a freshly configured Combat or Alert slot in explore state is silent (target 0, `+0x44` stays 0, nothing is emitted).
- **Writes:** the track record (`+0x40`, `+0x48`, `+0x4c`, `+0x50`, `+0x54`, and the name in 2b); the retiring list (via `0x10229550`); the channel (via `0x102297a0`).
- **Callees:** `FUN_10229550` (`thunk_FUN_10229550`, `10012aee`); `FUN_102297a0` (`thunk_FUN_102297a0`, `10007b58`); `Q_strnicmp`, `Q_strncpy` (VSTDLIB imports, bodies not in corpus).
- **Channel allocator `0x102297a0` (read while confirming, `__fastcall`):** channels `1..6` are tried in order; the first one that no retiring record (`+0x174` list, `+0x50`) and no live track (`+0x64`, `+0xbc`, `+0x114`, `+0x16c`) holds is returned. If all six are held, it scans the retiring list for the record with the smallest `+0x44` strictly below `1.1` (start value `0x1048dd2c`; `+0x44` is at most the scaled `Volume`, about 1.0 for authored files, so every record qualifies), defaulting to index 0 when none is below it. It calls `IEngineSoundServer003` slot 7 as `(0, channel, record)` to stop that record's sound, removes it from the list (memmove, count decrement) and returns its channel. The eviction key is therefore the **quietest retiring record**, not "index 0".
- **Returns:** void.
- **Port today:** no citing line. The closest code is `StartActiveVoices` (`ElysiumSoundScheme.cpp:245-297`). `StartStem` (`:270-284`) returns `Invalid` without submitting when a stem is absent (`:272`); a present stem is submitted at `Gain = 0` (`:278`) and raised by `ApplyMusicVolumes`. The Ambient bed is submitted at its volume (`:261`).
  - **No record and no retire of an empty slot.** The port has no slot to retire.
  - **No filename reuse.** See `FadeInScheme` above. The port's parser also folds `\` to `/` (`:57`), where retail compares the raw strings.
  - **No channel allocation.** The port uses `Submit`'s voice handle instead.
  - **No flags field.** The scheme's `bDry` and `bNoPause` are parsed (`:59-60`) but `StartActiveVoices` does not copy them into the `Request` (it sets no `Routing`), so retail's `0x800` and `0x2000` flag words have no counterpart.

## 0x10229550 Global::FUN_10229550 (284 B)

- **Signature:** `void __thiscall FUN_10229550(void* this /*manager*/, char* track, float duration)`, `RET 8`.
- **Callers:**
  - `FUN_10229430`, via thunk `10012aee` (`jmp 0x10229550`), at two sites (arm 1 and arm 2b).
  - `FUN_102293f0` (thunk `10004d95`), which retires all four slots in `+0x14`, `+0x6c`, `+0xc4`, `+0x11c` order. Its only caller is `FUN_1022b520` (FadeOut), which floors the duration at `0.5`, returns if `+0x455 == 0`, otherwise runs `102293f0`, `ThinkSet(0)`, and clears `+0x455` (confirmed; `audio_pipeline.md:261-262`).
- **Arms (retail order):**
  1. `if (track[0] == 0)`: return. An empty track is never retired.
  2. Otherwise:
     - `fVar1 = track+0x48` (the authored volume, the ceiling; read first).
     - `track+0x40 = 0.0f` (target zeroed).
     - `track+0x4c = fVar1 / duration` (outgoing rate: full-scale volume divided by duration, in units per second).
     - Append to the retiring list. `count = +0x180`, `cap = +0x178`. If `cap < count + 1` and growth `+0x17c != -1`, grow: from `cap`, `0` becomes `1`, else `cap * 2` while growth is `0` (else `cap + growth`), repeated until `cap >= count + 1`. Call `Plat_Alloc` if the base `+0x174` is `0`, else `Plat_Realloc` (`cap * 0x58` bytes). Set `base = +0x174`, `+0x184 = base`, `+0x180 = count + 1`. The memmove count is `0`, so this is a pure append. Copy 22 dwords (`0x58` bytes) from the track to `base + count*0x58`.
     - Clear the track: zero 22 dwords. The name is cleared, and so are the target, `+0x44`, `+0x48`, rate, channel, and flags.
- **Notes:** the retiring copy carries the track's ramped level `+0x44` as it was, the authored volume `+0x48`, a zero target, `rate = +0x48 / duration`, the old channel, and the old flags. The fade therefore takes `duration * (+0x44 / +0x48)` seconds from the level the track had reached, not `duration`. The `+0x17c != -1` test means growth `-1` would skip the realloc and write past the end. The ctor leaves growth at `0`, so this is unreachable in play.
- **Lifetime, recovered:** the retiring record is ramped and emitted by `FUN_10229090` every frame, and `FrameUpdatePostEntityThink` (`0x10228d00`) removes it when `+0x44 <= 0.01`. The same helper stops the sound (slot 7) on the frame the level crosses `0.01` while the target is `0`. Channel eviction in `0x102297a0` is the only other removal.
- **Writes:** the retiring list (`+0x174` base, `+0x178`, `+0x180`, `+0x184`) and the zeroed track record.
- **Callees:** `FUN_10430fa0` (memmove, CRT, in the corpus; a zero-length call here); `Plat_Alloc` and `Plat_Realloc` (TIER0 imports).
- **Returns:** void.
- **Port today:** no citing line. The closest code is `StopAll` (`ElysiumSoundScheme.cpp:398-411`) and `FadeOutScheme` (`:226-243`). Both call `Audio->StopVoice(H, fade)`, which is `Stop(Handle, FadeSeconds)` (`ElysiumAudioSubsystem.h:317`). In `ElysiumAudioSubsystem.cpp:751-756`, a positive fade calls `Comp->FadeOut(fade, 0)`, sets `DestroyAudioClock = now + fade`, and enters `Fading`.
  - **Fade duration:** `StopAll` uses `MusicCrossfade` (`:402`). Retail uses `authored volume / incomingDuration` as a rate, from the level reached.
  - **No retiring list.** Retail keeps outgoing records in a list with a rate field. The port keeps only voice handles that are reaped by clock.
  - **No rate, no channel, and no flags** on outgoing records.
  - **Lifetime:** the port reaps by clock. Retail removes a retiring record when its ramped level reaches `0.01`, or by eviction in `0x102297a0`.
