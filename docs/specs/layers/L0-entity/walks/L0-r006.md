Caveats that apply throughout:

- `0x1000969c` is `jmp 0x101acb70`; `0x100131e2` is `jmp 0x101ad470`. Thunks are followed to their targets.

- **U2. OFF/TOGGLE while active.**
  - If `+0x48c != 0`: if `+0x48c < +0x490` → return. Else step = `+0x490 + 1`; `+0x468 = 0`; `+0x464 = +0x498`; `+0x490 = step`; `+0x45c = min(255, ((255 - +0x460) / +0x48c) × step + +0x460)` (signed divide, then multiply); `m_flNextThink = curtime + 0.1`; return.
  - Else: `+0x4bc = 0`; `+0x204 |= 0x10` (start-silent bit set at runtime); if `+0x49c == 0 && +0x4ac == 0`: source valid → STOP emit `(e + 0x2e0, origin, name, 0.0f, 0, 0x4, 0)`, return (no reschedule). Else `+0x468 = +0x49c`; `+0x464 = 0`; `+0x478 = +0x4ac`; `+0x474 = 0`; go to tail.
- **U3. Start / looping.** `if m_fLooping == 0`: source valid → STOP emit (as above). Else `+0x4bc = 1`. (A non-looping ambient therefore never becomes active: every start is a STOP followed by a fresh START.) Then `FUN_101ad0f0(this)`. If owner is NULL and `+0x4cc` ∉ {`0x20`, `0x800`}: `Warning("%s has invalid NPC sound event parameters\n")` (name via `GetDebugName`), no insert. The origin is the **source entity's** (`EDI`, from `m_hSource`), not the owner's (asm `101ad85a`: `MOV EAX,[EDI]; MOV ECX,EDI; CALL [EAX+0x364]`), so `npc-ai/senses.md:442/453` ("owner origin") is wrong.
