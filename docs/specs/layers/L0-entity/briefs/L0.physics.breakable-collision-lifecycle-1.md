# Brief L0.physics.breakable-collision-lifecycle-1 — Breakable collision and death

Layer L0 · story `L0.physics.breakable-collision-lifecycle` · slice 1 of 2 · **ready**

## Goal

Apply breakable damage/death state after base collision feedback and collision-damage resolution. The story: Run base collision feedback before `CBreakableProp::VPhysicsCollision` dispatches impact damage (`0x1018fe80`); preserve breakable damage scaling and creation-frame output gate (`0x1018f400`), then its death flags and deferred removal state (`0x1018f580`).

## The retail functions (read each body before writing: `vtmb_code <address>`)

- `0x1018f400` CBreakableProp::OnTakeDamage (302 B, 107 maps, open) — Gate breakable damage, scale it by combined damage flags, invoke base damage handling, and fire OnHealthChanged except during the creation frame. Port lacks: Prop leaves lack this override. The inherited damage callback is a recording stub; flag scaling, creation-frame handling and OnHealthChanged are absent.
- `0x1018f580` CBreakableProp::Event_Killed (125 B, 107 maps, open) — Clear breakable spawn/entity flags, remember the attacker as breaker, disable damage, mark dying and schedule deferred removal. Port lacks: The inherited death callback is a stub. The separate Break input hides the prop and fires OnBreak without this death-state and removal sequence.
- `0x1018fe80` CBreakableProp::VPhysicsCollision (38 B, 107 maps, open) — Run base VPhysics collision handling, then dispatch TakeDamageFromCollision. Port lacks: Both inherited callbacks are recording stubs; Chaos prop collisions are not wired into retail collision damage.
